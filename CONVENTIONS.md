# Project Ocean Conventions

## Archive time selection

Do not insert/remove bottom-timeline caption rows during routine loading or crossfades. Keep the displayed timestamp and frame count in a stable-width, two-line block with tabular digits. Internal buffering still gates playback and is exposed with aria-busy; actual metadata/frame failures must remain visible with Retry. Requested source time remains available in the selection control, not an extra bouncing caption row.

Keep batch-independent display identity separate from product-specific request/cache identity. Never relabel a retained old frame as the requested timestamp. During the 480ms visual crossfade label both endpoints and explicitly state display-only blending; publish the new displayed timestamp when the fade finishes. Respect app/browser reduced motion, cap scalar imagery at two layers, and cancel/release animation and old layers on family changes/unmount. Scientific values never come from blended pixels. Preserve palette/manual limits/stable scale across compatible batches, cancel stale prefetch, and prefetch only one next frame. Graph headings/provenance must wrap outside the plotting area; use concise axis variable names with source units and retain full scientific names in context/hover/export. Check both delayed batch responses and narrow/wide graph layouts.

Never merge products solely because their dataset ID matches: require matching real/synthetic mode, variable set and exact selected region. Use each source timestamp's original product/local index for HTTP; keep the full-timeline index separate. Native scientific samples and strided display previews stay distinct. Each preparation remains within 8M values/128MiB; increasing catalogue capacity to 128 does not increase per-request work. Point-series graphs explicitly identify their selected-batch scope. Missing source dates are rejected, never generated.

Do not introduce profile weighting, inferred independence, propagated uncertainty or HTTP work implicitly.

## Naming and formatting

Local matching execution must construct inputs from verified readers, preserve unresolved support and recheck the sources after invoking the engine. Outside-envelope observations use two null candidate indices, never invented zero indices; half-missing pairs or asserted support without a candidate are invalid. Keep spatial diagnostic rows separate from accepted engine results. A blocked report uses zero pairs and overlap not evaluated, not no-overlap or success. The real guard may only change with a separately verified scientific-support implementation. See [5.7-C execution boundary](docs/MILESTONE_5_7_EXECUTION.md).

Spatial support diagnostics use the existing nearest-centre metric/ties before masks, never a farther wet fallback. Label bracketing native nodes as diagnostics, not cell polygons or a coastline certificate. Keep model-local and global-static indices separately named; derive wet-depth coordinates from all source mask levels, not an inferred `deptho_lev` convention. Retain geoid bottom values independently of pressure-derived depths. Unknown observation wetness/connectivity/bottom must remain null, not false or true. See [5.7-B scope and decision register](docs/MILESTONE_5_7_SPATIAL_SUPPORT.md).

| Area | Convention |
| --- | --- |
| Python modules, functions, variables | `snake_case`; use explicit names such as `pressure_dbar` and `time_tolerance_seconds`. |
| Python classes | `PascalCase`; type public interfaces and document shapes, units, and exceptions. |
| Python formatting | Enforced Ruff formatting/linting, four-space indentation, double quotes, and an 88-character target in `backend/pyproject.toml`. |
| TypeScript values and functions | `camelCase`; `PascalCase` for components and types; enable strict checking. |
| Frontend files | `PascalCase.tsx` for components, `camelCase.ts` for utilities/hooks, and kebab-case feature directories. |
| Next.js route files | Preserve framework names such as `page.tsx` and `layout.tsx`. |
| Frontend formatting | Two-space indentation; propose Prettier defaults plus ESLint, configured once per frontend. |
| Constants and environment variables | `UPPER_SNAKE_CASE`; reserve `NEXT_PUBLIC_*` for values safe to expose. |
| API JSON and Python schemas | `snake_case` field names; TypeScript API types mirror the wire schema, with explicit conversions to local UI state. |
| Text files | UTF-8, LF line endings, final newline, and a blank line around Markdown lists and fenced blocks. |

Backend runtime/development requirements are separately pinned, with development requirements including runtime requirements. `backend/pyproject.toml` configures Ruff and pytest, not a competing dependency list. Use the environment's explicit Python executable for Windows commands. In the final frontend part, use npm with one lockfile and add its formatter configuration then; frontend rules are not currently enforced because no frontend exists.

## Scientific data rules

- Preserve source variable names, units, coordinates, QC flags, data modes, and provenance before normalization. Never infer scientific meaning from a short name alone.
- Determine variable availability from inspected product/service metadata. A filename naming one target quantity can still contain other model variables; do not exclude BIO-ROMS temperature or salinity merely because a file is named for corrected pCO₂. Keep published product coverage separate from the verified contents/version of a live endpoint.
- Use explicit semantic names such as `temperature_in_situ`, `potential_temperature`, `practical_salinity`, and `absolute_salinity`; attach verified units and reference conditions. A generic display label may group them, but comparison must retain the distinction.
- Keep longitude/latitude named throughout internal code. Use the architecture's public longitude range `[-180, 180)` and signed latitude. For future dateline-crossing requests, split/wrap explicitly rather than silently sorting endpoints.
- Treat Argopy region ordering as a provider-specific format inside its adapter. Pressure limits are sea pressure in dbar. Scientific depth is metres positive downward; keep pressure and its reference separately. GSW temperature conversion requires the appropriate salinity definition, temperature scale, and reference pressure; follow the architecture's conversion contract.
- Decode time using source units and calendar, preserve temporal averaging metadata, and expose real-world times in UTC. Do not coerce unsupported calendars into incorrect dates.
- Preserve NaN/masks during scientific processing; serialize missing JSON values as `null`. Never replace missing temperature, salinity, chlorophyll, or velocity with zero.
- Apply time/position QC as well as per-variable QC using a documented policy. Record which raw or adjusted value was chosen and what Argopy already filtered. Raw Argo profile time is `JULD`, while Argopy may expose `TIME`; preserve that mapping. Do not use one unexplained QC threshold for every source or BGC parameter.
- Retain glider sample time/position alongside GPS fixes; align according to dimensions and metadata. A deployment is not automatically one vertical profile.
- Confirm vector units, staggering, and orientation before displaying east/north arrows. Scientific coordinate conversions belong on the backend; renderer exaggeration and color mapping remain presentation settings.
- Compute model minus observation only after compatibility checks and matching within the model's local wet/depth/time support. Nearest matching must also respect coastlines and bottom masks. Keep no-overlap, missing-value, QC-rejected, and incompatible-variable outcomes distinguishable.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the scientific contract and matching sequence. Do not duplicate independent conversion or QC implementations in individual UI components.

Part 5.1's [audit](docs/MILESTONE_5_1.md) distinguishes horizontal/time-envelope candidates from valid matched pairs. Retain provider metadata separately from client-replaced attributes; neither inherited model globals nor client defaults establish actual source coverage/definitions. Raw/adjusted policy eligibility is not comparison readiness. Unknown daily averaging windows, temperature scales and vertical support remain explicit gates. Do not repair source timestamps or overwrite the raw collection to make comparison pass. Part-5 checkpoints are separately approved approximately 20-minute timeboxes; stop safely with unresolved work documented instead of guessing.

The complete scientific contract still includes future comparison requirements. Part-3 surface products keep `source_definition_not_harmonized`, `source_mask_and_nonfinite_only`, and `source_timestamps_no_inferred_bounds`. Part-4 observations use `core_flags_1_2_no_fallback_v1`, explicit raw/adjusted choice, coordinate/selected-pressure/per-variable QC, source valid-range/packing provenance, and exclusions. Neither path harmonizes quantities, invents averaging bounds, or enables comparison.

## Implementation patterns

The [static acquisition path](docs/MILESTONE_5_7_STATIC_ACQUISITION.md) is a narrow exception to Toolbox-based model access: fixed official public Zarr objects, verified TLS, no credentials/redirects/global fallback, bounded chunks/transfer and an operator subprocess deadline. Retain exact compressed source objects; an incomplete `source_read_set` must never be interpreted as a complete global Zarr dataset. Check exact grid alignment and readback before atomic publication. Acquisition summaries and numeric bottom-level agreement do not promote matching support flags. Failed private stages require operator review, not automatic reuse/deletion.

For scientific support, distinguish catalogue compatibility from acquired-array verification. The [5.7 evidence checkpoint](docs/MILESTONE_5_7_SUPPORT_EVIDENCE.md) identifies a static source but grants no verified support flags. Compare actual coordinates before joining; do not round or use nearest/override alignment to hide differences between static parts. Preserve the distinction between the distributed product grid and the original model computational mesh. New acquisition and provider messages require the separately scoped approval recorded in that checkpoint.

The 5.7 local reader verifies prepared native fields against bounded manifests/metadata and pre/post file hashes/stat identities before producing an internal snapshot. Preserve original axes/labels and per-variable validity masks; never promote finite values to wet/bottom/connectivity evidence. The separate local audit may verify adjusted-depth alignment after source/sample checks, but must retain unresolved time, wet, bottom, connectivity and vertical-reference gates. It prints a bounded private `inputs_verified_matching_blocked` report without calling the kernel, saving data or changing the original policy preflight. Its exit3 means verified inputs with blocked matching, not failed download or successful pairs. [Current checkpoint](docs/MILESTONE_5_7_READER.md).

Use the 5.7 private matching input only for bounded, explicitly synthetic kernel work until a verified real-field/support adapter exists. Real mode must remain blocked; caller-supplied evidence booleans and hashes do not authenticate files. Recompute adjusted-depth and quantity alignment rather than trusting hand-built reports. Keep selected pressure/error provenance separate from the original raw collection, and use `serialize_matches(request)` to recompute results instead of serializing arbitrary claimed pairs. Enforce native-grid/work/input/output budgets; they are not an OS memory sandbox. Preserve `blocked`, per-row unresolved support and `no_valid_pairs` as distinct outcomes. No residuals or metrics belong in this checkpoint.

Matching policy belongs in `comparison/`, not source adapters or HTTP routes. Use the versioned [canonical policy](docs/MATCHING_POLICY.md), with exact input identity, explicit reviewed limits/rationale and separate evidence gates. Null is unknown, not zero or false. The 5.6 strict D-mode/QC1 screen does not alter the earlier A/D flags-1/2 data/report policies. Preserve joint eligibility counts; separate positive marginal counts do not imply a shared eligible sample. A blocked preflight never reports no-overlap or ready pairs. Recompute assessment requirements during serialization, preserve original time labels and raw collection values, and require verified adjusted-depth alignment. No wet-cell fallback, extrapolation or uncertainty-based tolerance expansion.

Quantity diagnostics use versioned `quantities_1` reports, explicit provider/client evidence and A/D adjusted values without fallback. Keep provider definitions authoritative for semantics and apply the intersection of provider/client decoded ranges conservatively. Re-evaluate adjusted parameter and coordinate QC; do not reuse raw-selected eligibility as adjusted eligibility. Preserve errors/source modes and distinguish observation-side conversion from model quantity compatibility. Unknown temperature scale/reference or full propagated uncertainty must remain unknown. Pure functions do no file verification; the audited operator adapter checks original rows and hashes. No in-place collection or model-manifest corrections.

Pressure-derived depths are separate versioned results (`pressure_depth_1`), never in-place replacements of source `ObservationSample.depth_m`. Require explicit sea-pressure units/reference evidence and zero-geopotential assumptions; lazy-load pinned GSW only for operator/calculation work. Preserve existing selected pressure/QC and raw/adjusted provenance. Never apply an adjusted error to raw pressure, invent missing uncertainty as zero, clamp an out-of-domain error endpoint, or label endpoint sensitivity as a confidence interval. Calculations outside the prototype 0–12,000 dbar or −90–90 latitude domain are rejected. Source/model datum, full uncertainty and comparison eligibility remain separate gates.

Part 5.2 adopts the [native-model contract](docs/MODEL_PREPARATION_CONTRACT.md): frozen validated models with tuple sequence fields, canonical identity hashing, a separate `m_` namespace, contiguous native source indices and explicit unresolved policies. Preserve original units/masks and source metadata separately from decoded float64 packing. Contract validation is not file verification; I/O enforcement/publication is implemented in Part 5.3. Do not use unchecked Pydantic construction/copy updates as validation. Existing surface/observation contracts are not migrated.

Keep source acquisition in adapters, transformation in processing, matching in comparison, and HTTP behavior in API routes. Source adapters must expose inspected capabilities; absent current or depth fields disable those features rather than producing fabricated data. Use local Zenodo V2 as the BIO-ROMS development default and reuse processing for registered LAS exports or future OPeNDAP acquisitions. Retain each input's version/checksum/provenance; do not silently replace it with another source or V1.

Represent source IDs and endpoint mappings in the registry. Keep secrets in runtime configuration. Network access should have bounded timeouts, limited retries for transient failures, and useful error context. TLS verification stays enabled; diagnostic `verify=False` history is not an application default.

Source definitions are schema-validated and bounded, with unique IDs, public origins, and local `.nc` paths resolving under project `data/raw/`. Registry notes describe published claims; inspection reports describe observed headers. Explicit operator commands inspect raw inputs; the catalogue may read public source configuration, and frame/time-series requests may lazily load scientific libraries to read prepared files. API startup and `/health` do none of this. Inspect only configured final filenames, not browser partial downloads or deliberate cloud recalls.

Header-only inspection preserves attributes without reading axes/fields or claiming coverage/capabilities. Use unavailable/uninspected/invalid/unsupported/not_prepared precisely. In the local-only inspector, remote entries are not_configured/local_inspection_not_applicable; acquisition support is separate, not adapter_not_implemented. Successful acquisition is acquired_not_prepared. Checksum scans, downloads and saving are explicit operator operations, never startup/health work.

Use named request/schema objects for region, time, depth, and variable selection. Avoid downloading data during module import or application startup. Implemented `PreparationRequest` accepts unique source variable names, an increasing non-wrapping region, and inclusive dates; depth selection remains unsupported for this surface adapter. Products are keyed by source checksum, selection, processing version, limits, and real/synthetic mode. A saved verified inspection must still match the configured source and its size/mtime before preparation; ordinary concurrent changes block publication. This is trusted-local-input validation, not an adversarial immutable snapshot.

Part 3 keeps direct netCDF4 frame/cache control and scientific/preview separation. Part 4 uses xarray only after metadata limits and before bounded coordinate/field selection; no competing unbounded reader. Unsupported grids, calendars, units, QC or coordinate-range conflicts fail explicitly. Source packing/range provenance is preserved, not reapplied twice. Display previews never replace scientific observations or model samples.

For the surface adapter, write scientific and preview outputs into private temporary directories. Publish the cache directory first and the scientific directory with its validated manifest last; the latter is the commit marker. Existing matching products are reused after identity/hash checks; conflicting or incomplete products are not overwritten. No automatic background worker, download, or preparation is triggered by HTTP requests. General cache eviction is not implemented.

Keep API responses bounded and versioned. Implemented public contracts use `schema_version: 1`, validate dimensions/axes/value counts, preserve units/source identity and `null` missing values, and omit private paths/file records. Frame quality is explicitly `preview` or `scientific`; a native-resolution frame requires a small enough bounding box. Time-series inspection returns the selected grid-cell coordinates, requested point, and distance; it performs no wet-cell search, interpolation, or observation comparison. Errors carry a stable code and safe message without echoing invalid inputs, credentials, or local traces. Prepared NetCDF reads are serialized per process with a non-blocking lock; concurrent scientific reads return `busy`/503 rather than building an unbounded queue. Future browser code must cancel stale requests and release GPU resources when layers are replaced.

Separate liveness from data readiness. Implemented `GET /health` returns the fixed HTTP 200 schema in [ARCHITECTURE.md](ARCHITECTURE.md), with `Cache-Control: no-store` and no network calls, file reads, or processing. Settings are validated once at app construction from process environment, not loaded per request or implicitly from `.env`. `/ready` is now implemented: no `OCEAN_REQUIRED_PRODUCT_IDS` configuration means 503, and only an explicit JSON list of passing real prepared products can yield 200. Checks are bounded manifest, stat/identity, and one-byte file-access checks; they do not parse NetCDF, import scientific libraries, rehash large products, or access raw inputs/providers. Readiness is local prepared-selection availability, not every source or arbitrary requested selection. Optional providers stay source-specific. `/docs` is developer tooling, not monitoring. Future globe loading must not be gated on these checks.

Colorbars must show quantity and units. Use a shared scale for directly compared layers and a diverging scale centered on zero for signed differences. Keep a stable scale across animation frames unless the user explicitly selects automatic scaling. Surface views and near-surface observations must retain their actual depth/pressure information.

## Observation/acquisition implementation conventions

Native Copernicus preparation is now implemented as an operator-only path. Decode packing once, mask fill/nonfinite and same-dtype raw-domain validity bounds; reject ambiguous/unsigned encodings. Preserve every selected sample with separate per-variable masks. Use dtype/shape-tagged metadata, storing numeric nonfinite attributes as `NaN`/`+Inf`/`-Inf` strings rather than silently losing them. Scientific output has no active source scale/offset/range encoding. Validate and hash output, check every selected slab against source, and publish behind an exclusive short lock; never overwrite existing products. A stale lock requires explicit operator review, not automatic lock stealing. Publication/reuse is not HTTP readiness or comparison eligibility.

Keep acquisition requests operator-only, schema-validated and separate from HTTP routes. Source-specific errors must distinguish no data, missing credentials, limits, timeouts and unsupported input; do not call an upstream outage a successful empty selection. The worker has a wall-clock deadline, bounded sockets and disabled credential-bearing output; these do not establish an OS memory sandbox. Package compatibility is pinned jointly: Argopy 1.4.0 uses erddapy 3.2.1 and xarray 2025.9.0 in this build.

Copernicus requests explicitly set `vertical_axis="depth"` and record the SDK's elevation-to-depth sign/order/name conversion and CF decoding/re-encoding. This is not pressure conversion or scientific quantity harmonization. Strict-inside bounds rejection is `provider_request_rejected`, not proof of no samples: even partial overlap can be rejected. Rejected credentials, missing credentials and an unreachable authentication service remain distinct safe errors. Verification-only login uses `check_credentials_valid=True`, never a credentials-file-writing login; keep values out of command arguments, request JSON, documentation and provider output.

Observation IDs are o_/s_/r_ plus 24 hex characters for collection/sample/profile. Preserve input hash, source sample/profile index and actual identities. CONFIG_MISSION_NUMBER alone is not a separate-profile key. No explicit profile ID means track-only/ambiguous points. QC policy requires time/position/selected-pressure and parameter flags 1/2; rejected in-range rows remain scientific samples with explicit reasons. Adjusted mode never falls back to raw, unsupported source modes fail, and raw fluorescence calibration remains unevaluated. Source range bounds are interpreted with source packing; inconsistent coordinate ranges are not overridden.

Scan EGO coordinates in bounded 4,096-row blocks (up to one million source rows), keep at most 5,000 selected rows, then read selected science. Argo source rows remain capped at 100,000. Preserve fractional UTC times and pressure separately from depth. Observation JSON snapshots are capped at 16 MiB and catalogues at 32 collections; APIs return 1–500 samples/page and at most 2 MiB. No display decimation changes these samples. Publication is immutable/atomic; HTTP metadata excludes private filenames/stat identities. A page hashes/parses the bounded collection, so measure cost rather than assuming constant-time pagination.

## Performance and quality conventions

Treat smooth interaction and scientific correctness as acceptance requirements. Use the canonical targets in [ARCHITECTURE.md](ARCHITECTURE.md); report measured results with the device, network, selected data, and cache state. Rendering targets are engineering goals, not a claim that a large file is automatically fast.

- Subset variables, dates, and region before materializing scientific arrays. Keep raw V2 private on disk, preserve scientific-resolution processed data, and create separate display previews. Configure/test chunking before large computations; whole-file loads and conversions do not belong in interactive handlers.
- Precompute a small useful starting selection. Expensive preparation runs as an operator task or an implemented background worker. Return an explicit unprepared state when no worker can fulfill the request; never invent progress.
- Debounce rapid committed selection changes while giving immediate control feedback. Cancel outdated requests and verify response identity before applying results. Old layers retained during an update keep their old labels until the new data is ready.
- Share bounded caches across views, deduplicate identical requests, and prefetch only nearby animation frames at lower priority. Invalidate by dataset version, processing policy, and selection. Bound decoded/GPU memory, total in-flight work, and compressed bytes; evict derived caches without deleting raw inputs.
- Use Preview/Balanced/High display settings or automatic detail adjustment to manage frame rate. Preserve readable labels, units, missing masks, attribution, and fixed comparison color scales. Display reduction must not alter profile samples, comparison statistics, or scientific exports.
- Test delayed/out-of-order responses, rapid slider movement, cold/warm caches, failed layers, and extended playback for memory growth. Graph exports identify any displayed decimation and retain access to bounded scientific values with provenance.

Configuration limits now live in `config/performance.yaml`, with schema-enforced ceilings and request checks before field materialization. Current ceilings include 12 selected timestamps, 8,000,000 prepared scalar values, 16,384 preview cells, 65,536 scientific frame cells, and 2 MiB JSON responses. Source chunk and per-variable NetCDF cache limits are separate; neither claims a hard operating-system process-memory cap. Do not send internal configuration files directly to the browser. Record measured outcomes and their exact scope in [docs/performance.md](docs/performance.md); in-process API timings are not browser latency, globe FPS, cold-disk performance, or a deployment SLA.

Preserve imagery/terrain credits in every applicable view. Keep provider credentials scoped appropriately; Copernicus credentials remain server-only. A browser map-provider key or token, if required, must be limited to the provider's intended public access and documented separately from server secrets.
